## Taxonomy and active legal source set

The taxonomy is closed by runtime spec §8.1: four retained legal effective
sources and 13 deletion classes. The active effective-config source set after
P4.3 is only:

1. the canonical global config root and its canonical files/assets;
2. `<workspaceRoot>/.kilo/` and its project-versioned files/assets;
3. VS Code SecretStorage credentials, referenced by opaque identifiers; and
4. versioned runtime defaults and safety invariants.

UI `globalState`/`workspaceState` is derived UI state, not effective-config
authority. Session/storage state and bounded approval records are operational
state, not effective-config sources. `KILO_CONFIG_DIR` instruction profile
fallback is separately retained instruction behavior, not `Config.Service`
authority.

2026-08-25. The method was:

> **Provenance note.** The `8167992b` HEAD is the historical baseline for the

   placeholder rows in tracker §7;
2. inspect the canonical loader and P4.3 absence anchors in
   `packages/opencode/src/config/config.ts` and
   `packages/opencode/test/kilocode/p4-3-cutover.test.ts`;
3. inspect retained diagnostic/config-console, TUI/instruction, sandbox,
   migration, SDK-wrapper, provider/catalog, i18n, and build/package paths;
4. record only path-level static evidence. No dynamic call-graph or transport
   deletion claim is inferred from a string absence.

The matrix uses these statuses:

- **effective inactive** — the P4.3 canonical-loader evidence proves that the
  source no longer affects effective `Config.Service` output; no relevant
  non-effective residue was found in the inspected paths;
- **residual retained** — effective use is inactive, but source inventory,
  diagnostic, TUI/instruction, SDK-wrapper, safety, migration, catalog, or
  transport machinery remains and is open P4.4 work;
- **unknown** — the inspected evidence does not prove either classification.

`residual retained` does not mean that the residue is an effective-config
reader. It means that physical source removal or adjacent-surface narrowing is
not complete and must not be reported as complete.

## Residual machinery and open P4.4 work

### `KilocodeConfigSources` and config-console

`KilocodeConfigSources` remains a historical/diagnostic inventory. It still
enumerates env, legacy filename, project, cloud, managed, and runtime sources
(`packages/opencode/src/kilocode/config/sources.ts:12-313`) and is consumed by
the config-console handler (`config-console.ts:43-67,128-143`). The handler's
effective value is `config.get()`; the source list is passed to overlay/source
diagnostics. This is evidence of retained machinery, not evidence that the
listed sources remain effective-config authority. Narrowing or deleting this
inventory is open P4.4 work.

from retained effective-config loading. The canonical loader and canonical

matrix does not claim that every adjacent merge-like helper is physically gone:
the diagnostic overlay, TUI readers, and SDK `mergeConfig` child-process helper
remain separately inventoried. No 12-source effective merge is treated as
active based solely on those residues.
