## B9-P2 wire outcome contract closure (2026-09-04, docs-only)

B9-P2 只做 abort oracle 与合同闭合，不新增 private carrier，不修改 `handleAbort`、FD capabilities、现有 `cancelTree` 行为（B9-LOCK-001..008 保持不变；Gate B 仍 open，G3 仍 Active）。

| Wire decision | 合同语义（prospective，未实现） |
|---|---|
| Request receipt ≠ terminal convergence | HTTP response（当前 volatile `200 true`，未来 typed ack）只是 request receipt，不是取消成功证明；receipt 不声称取消已完成。Terminal outcome 需经 runtime/SSE/persistence convergence 另行确认。Receipt 可先返回 transport receipt `accepted`/`accepted-unresolved` 非终端状态（`ambiguous` 仅 runtime semantic terminal outcome；`transport-unknown` 仅 delivery uncertainty），最终 outcome 以 runtime 收敛为准。 |
| opId / request identity | Cancellation-request `opId` 标识一次 directory + session + request identity 的取消请求（canonical directory + sessionId + cancellation-request identity）。既有 generation operation records（R11 identity 形式）只作为 affected-set association，不新增 generation kind，不作为 request identity。 |
| Missing session | Typed `session.not_found`-class failure，无 side effect；scope 绑定失败不扩散。当前 handler 无 `requireSession`、直接 cancel（`handlers/session.ts:504-507`），属实现差距，非目标语义。 |
| Terminal session | Idempotent terminal no-op：返回既有 terminal outcome，不创建新的 cancellation success。当前 tree 的 missing-runner → `idle` + `true`（`run-state.ts:78-87`）与真实取消不可区分，属实现差距。 |
| Cancel miss | Affected-set 中记为 `not_affected`，不能计为 success。当前 abort 无论 prompt 侧 `assertNotBusy`/`RunnerBusy` 如何都报 `true`，属实现差距。 |
| Per-target observability | Root / descendant / queued / intake / background / followup / event publication 必须分别可观察，各自 disposition 进入聚合 outcome。当前 `cancelTree`（`kilocode/session/prompt.ts:142-167`）为 `unbounded` + `discard` 无序扇出、无 per-target aggregation；queue cancel 是 version-based，intake 是 snapshot，followup sibling 可不在 descendants、新 runner 可重新准入—— race / late SSE / partial result 的顺序与聚合是实现前置证据要求（Gates C-D），不是已证明事实。 |
| Authority 不重叠 | SDK 是 abort command 的唯一 authority；SSE `session.status idle`（`KiloProvider.ts:5945-5959` 观察侧）只做收敛观察；private observer（如未来存在）仅 detached parity observation，不得发起第二次 abort、不得 replay。`KiloProvider.ts:5315-5322` 的 optimistic idle/flush/TurnClosed 只在 stop success 后执行，partial fan-out failure 保持 busy；无 abort timeout envelope；pending prompt recovery 与 abort 解耦。 |
