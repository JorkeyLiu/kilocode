# P4.4-G3 path/get private carrier — single-operation runtime batch

- **Owner:** production `getPath` handler (`packages/opencode/src/server/routes/instance/httpapi/handlers/instance.ts`
  `getPath`) is the single authority for the five-field `PathInfo`: process-global `Global.Path.home/state/config`
  plus directory-routed `InstanceState` context (`ctx.worktree`/`ctx.directory`). `kilo serve` fd3/fd4 carrier
  (`packages/opencode/src/kilocode/server/fd-carrier.ts`) and extension
  `ServerManager`/`KiloConnectionService`/`ServePrivatePeer`/`model-state.ts` are the only carrier consumers.
  No second path store, no new config/session authority, no durable store, no fences/convergence.
- **Scope:** exactly `path/get`. `command/list`, `config/warnings`, `session/abort`, B9, durable outcome, and
  broad gate closure are out of scope. SDK `client.path.get` (`GET /path`) remains the sole user-visible
  authority; the private result is diagnostics-only parity observation, never a source of state, cutover,
  or fallback.
- **Semantics:** mixed ownership. `home`/`state`/`config` are process-global and explicitly excluded from
  parity (`globalExcluded: true`); `worktree`/`directory` are directory-derived and compared exactly.
  The request directory is routing-only and never compared. `worktree === directory` is never asserted
  (`worktreeDerivationUnknown: true`). Worktree derivation, freshness, and transport remain explicit unknowns.
- **Lifecycle:** the carrier reuses the existing drain-control lane (`acquireDrainControl` + `InstanceRef`,
  same lane as `experimental/session/list`) because the production handler reads `InstanceState.context`
  synchronously, which requires `InstanceRef`. No new drain-control lane, no fence/convergence, no
  worktree infrastructure. No lifecycle contradiction was observed; production reads the context
  synchronously with no list/session mutation.
