# P4.4-G3-B3 — Private `session/fork` fd3/fd4 carrier into same AppLayer (B3, G3 Active)

- **Scope:** B3 durable `session/fork` lane + private `session/fork` fd3/fd4 parity into same `AppLayer`. SDK `POST /session/:sessionID/fork` remains authoritative, private `dispatchPrivate` is replay-only parity observation. No second transport, no generated SDK hand edits, no public interface cutover. One immediate transaction commits forked session + `session_operation` with `result_snapshot` (serialized forked `SessionTable` row) + `EventV2` `session.created` projection, with exact replay from persisted snapshot without rebuilding from mutable `Session` state. Private fd3/fd4 is `dispatchPrivate` replay-only and never becomes fallback executor after any SDK terminal, including `500`.
- **Status:** G3 remains **Active**, generated SDK `POST /session/{sessionID}/fork` remains authoritative, private path is terminal-replay parity observation only. No transport cutover, no gate closure for C/D/E/F/P4.4, no cross-platform production claim beyond Darwin (Darwin production proof via `server-manager-b3-integration.test.ts`; Linux/Windows not overstated). B3 is G3-B3 production proof and Gate C/D preparation; does not close Gates C/D/P4.4.
- **Owner:** `SessionForkDispatch` Effect service wired once in `AppLayer` (`effect/app-runtime.ts`) is the single authority. `kilo serve` fd3/fd4 carrier (`kilocode/server/fd-carrier.ts`) and extension `ServerManager`/`KiloConnectionService`/`ServePrivatePeer`/`KiloProvider` are the only carrier consumers. No extension-local durable store, no second `AppLayer`.
- **Scope lock:** B3 is durable fork only; no broad `prompt`/`command`/`provider`/`config` redesign; no second transport; no `Promise` facade in shared `packages/opencode/src`.
- **Namespace:** Repository-wide invariants retain established meanings; B3 fine-grained invariants map to SDK authoritative (private replay-only parity), fork-only durable lane, per-operation `fork:<id>:<token>` distinct with shared `idempotencyKey`, one commit with exact replay from persisted snapshot, validate and bind all explicit identity fields, reuse fd3/fd4 ownership/lifecycle and capability `session/fork`, parity observation-only, evidence/tracker/arch docs with no G3/Gates C-F/P4.4 claim — no repository-wide meaning changed, no gate closure, no new claim.

## Operation identity and storage

| Aspect | Behavior |
|---|---|
| OpId | `fork:<sessionID>:<token>` canonical via `canonicalForkOpId(sessionID, token)`. `token` is non-empty, no `:` , UUID-derived non-colon token from `crypto.randomUUID()` (full UUID, not truncated 8-hex). `parseOpId` binds `parts[0]` to `context.sessionId`. |
| IdempotencyKey | `fork:<sessionID>:<token>` identical to `opId` for one operation; shared by SDK and private for replay. Distinct operations have distinct tokens → distinct `op_id` primary keys, no PK rollback. Same-key retry reuses identical `opId`+`idempotencyKey` → same `idempotency_hash` lookup. |
| Table | `session_operation` (`op_id TEXT PRIMARY KEY`, `op_kind CHECK` includes `fork`, `result_snapshot TEXT` JSON of serialized forked `SessionTable` row, `revision INTEGER`, `UNIQUE(session_id, idempotency_hash)`) plus `directory`, `parent_session_id`, `config_version`, `session_revision`, `request_id`, `message_id`, `title` carrying forked session ID (no separate `forked_session_id` column; implementation stores child ID in `title` field). Migration `20260902000000_add_fork_operation` adds `fork` kind and snapshot columns. |
| Commit | `insertSessionForkSucceededTx` in one `BEGIN IMMEDIATE`: validate source `SessionTable` exists → resolve target `InstanceStore.load` → check `GenerationGate.isBarrierActive` → freshness `sessionRevision`/`configVersion` → create forked session row (`SessionID.descending()`, `getForkedTitle`, copy filtered messages/parts via `cloneMessageDataForFork`/`clonePartDataForFork`, `KiloSession.prepareForkedPart`, inherit sandbox, `carryForkDiff`, `KiloSession.register`) → `INSERT session` → `EventV2.recordProjectedTx` `SessionV1.Event.Created` with explicit `Location` (canon dir + project worktree + workspace_id) → `INSERT session_operation` with `result_snapshot` JSON → commit then `EventV2.notifyCommitted` via `wakeAggregate`. Exactly one forked session + one operation + one `Event` atomically; same-key replay returns validated persisted `Session.Info` with `makeRevision(existing.revision, currentConfig)` without inserting new session. |
| Replay | Fast-path `getSessionForkByIdempotencyHash` before tx and in-tx `getSessionForkByIdempotencyHashTx` check `isSessionForkConflict` (opId, directory, parentSessionId, configVersion, sessionRevision, messageId). If `succeeded`, decode and validate `result_snapshot` as `Session.Info` and return `data: {session}` with persisted revision; invalid snapshot → `internal` without fallback to mutable `Session`. `opId` PK collision → `conflict` before any mutation. Same-key replay advances no revision. |

## HTTP authority and identity binding

| Aspect | Behavior |
|---|---|
| HTTP `POST /session/:sessionID/fork` | `requireSession` first, canonical `SessionID` validation. Durable requires `directory` absolute, `sessionId` binding to URL, `parentSessionId` null only, `idempotencyKey`/`requestId`/`opId` present; omitted context or mismatch → `400 validation.failed` or `scope_mismatch`. Stale `sessionRevision`/`configVersion` compared to `SessionRevision.get`/`ConfigConvergence.getBootedVersion` with single `GenerationGate` lease → `409 stale` or `409 InstanceUnavailableDuringConfigRebuild` when barrier active, otherwise `failed conflict` for duplicate key with different facts, `failed internal` for invalid snapshot or missing record. `dispatch` maps `session.not_found→404`, `validation.failed/scope_mismatch→400`, `stale/conflict→409`, `internal→500`. |
| Private validation | `serve-private-peer.ts` `validateForkRequest` mirrors backend exactly: `isAbsolute` directory, `SessionID` via `typeof value === "string" && value.startsWith("ses")` (backend authoritative, accepts colon/space schema-valid forms), `parentSessionId` must be null (non-null → `validation.failed`), `configVersion`/`sessionRevision` safe ints, `payload.messageId` optional MessageID with backend `typeof value === "string" && value.startsWith("msg")` (accepts colon/space forms), strict `unexpected field` at root/context/payload, `opId` session binding via `parseForkOpId`. `validateForkResult` enforces `v/requestId/opId/op/idempotencyKey` identity, `status/accepted/outcome` coherence, `succeeded` data has `session`. |

## Carrier and private parity

| Aspect | Behavior |
|---|---|
| Carrier | Same `kilo serve` extra-fd `5-stdio` (`stdio[3]` writer, `stdio[4]` reader) as B1/B2, `epoch` per spawn, `FD_CAPABILITIES = ["session/cancelQueued","session/update","session/fork"]`. `ServerManager` discovers port via `stdout`, `KiloConnectionService` owns `ServePrivatePeer` lifecycle (epoch coherence, `transportUnknown` on drift). Private observer timeout explicitly cancels the pending at `JsonRpcPeer` boundary (`tryCancelPending`) or epoch-invalidates the private peer; thereafter private parity remains disabled (fail-closed) until the next full backend connection/server reset (no automatic retry/reconnect, no detached work); timed-out pending cannot accumulate and SDK result stays authoritative. |
| Protocol | JSON-RPC 2.0 `initialize` with `capabilities:["session/cancelQueued","session/update","session/fork"]` → server validates `kilo-private/1`, returns capabilities including `session/fork`. `KiloProvider` fork dispatch is SDK-first: builds `{opId, idempotencyKey, requestId}` via `canonicalForkOpId` shared token, calls `client.session.fork` (SDK `POST`), then if `isPrivateAvailable()` and SDK terminal, calls `privateFork` with same tuple and 3 s bounded timeout; timeout/throw synthesizes `ambiguous transportUnknown true` and logs `[Kilo Fork] transport-unknown parity`, `compareForkParity` logs only `[Kilo Fork] parity divergence` or `[Kilo Fork] transport-unknown parity` (no parity-match log), never replaces SDK result. After SDK `500 internal`, private is still called but `dispatchPrivate` is read-only, so no second mutation. |
| Parity | `compareForkParity(priv, sdk)` — `transportUnknown true → transport-unknown`, `succeeded vs succeeded → session equality (id/parentID/directory)`, `failed vs failed → class mapping via response status`, no raw title logging. |

## Retention classification

| Aspect | Classification |
|---|---|
| `session/fork` rows | Existing `session_operation` family rows under existing 8/6 GiB complete-family budget, seven-day/active/leased protections, and session cascade (`ON DELETE CASCADE`). No separate `session/fork` retention policy. Family deletion cascade hard-deletes operations and retains normal `deleted` tombstone. |
| `result_snapshot` | Persisted JSON forked `SessionTable` row inside `session_operation`; retained/deleted with its operation row via family cascade. No separate lifecycle. |
| Changefeed | Bounded payload-free `session_changefeed` — fork creation emits `changed` via `SessionRevision`; durable family deletion emits `deleted` tombstone. |
| Live trimming proof | No live retention trimming/high-watermark/pressure-diagnostics proof is claimed for B3. Classification only; live store operation remains deferred. |
