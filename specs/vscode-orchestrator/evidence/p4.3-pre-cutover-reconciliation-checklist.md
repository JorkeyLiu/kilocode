## Purpose and Bound

This checklist records the 15 P0 source mappings to the four retained legal classes or 13 removal classes and provides explicit per-source fields for the sole user to reconcile desired values into canonical files, SecretStorage, or defaults before the reader deletion boundary.

- **What this artifact is:** A manual-only template that enumerates every current effective-config source, classifies it against the closed taxonomy, states its canonical target or explicit no-target disposition, and leaves blank fields for the sole user to act and verify.
- **What this artifact is not:** It does not reconcile values, does not delete readers, does not introduce automation, and does not claim cutover completeness. P4 remains Active; no claim of P4.3/P4.4/P4.5 completion is made.

## Manual-Only, No-Import, No-Dual-Read Statements

- **Manual-only:** Reconciliation is performed solely by the sole user by hand-editing canonical files, SecretStorage, or defaults. No script, import tool, migration tooling, or automatic reconciliation exists or will be created to populate this checklist.
- **No import tool:** There is no migration/import tool and none will be created. Any desired current configuration is recreated manually in the canonical locations.
- **No dual-read window:** There is no dual-read compatibility window and none will be created. Until the cutover, current implementation may still read legacy sources; at the cutover all legacy readers are deleted together atomically and cannot affect effective config.
- **No compatibility reader:** No generic compatibility reader or overlay survives the cutover. Deleted sources have no target reader.
- **Production readers unchanged in this unit:** This unit creates only this evidence artifact. It does not modify production config readers or P4.4/P4.5 artifacts.

## Remaining Risks — What Must Be Manually Filled Before Cutover

- **Unfilled rows:** Every blank `_PENDING` field is a risk. An unreconciled row means the desired value currently living in a deleted source will be lost at cutover and will not be automatically recovered.
- **Hidden values in removal sources:** Environment variables (`KILO_CONFIG*`, `KILO_PERMISSION`), legacy global files (`config.json`, `opencode.json`), TOML one-shot state, org well-known fetches, and managed-directory overrides may hold values not visible in the canonical files. They must be inspected by hand before deletion.
- **Scope misplacement:** A value placed in the wrong canonical scope (global vs project) will compose differently under the field registry's typed operators. The registry (runtime §3.2) decides global-only / project-only / both-with-typed-composition per field; misplacement is a validation error at materialization, not a silent fallback.
- **SecretStorage gap:** Credentials referenced by canonical files must already be in SecretStorage before cutover; file-only secrets will fail materialization.
- **No invented values or hashes in this template:** This template contains no hashes or reconciled values. Any hash or value appearing after manual fill must be the sole user's own record, not an invented placeholder.
