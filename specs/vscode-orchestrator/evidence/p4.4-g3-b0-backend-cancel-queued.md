# P4.4-G3-B0 — Backend `session/cancelQueued` (B0, G3 Active)

- **Scope:** Backend-only durable control, AppLayer-owned. No fd carrier, no transport cutover, no B1 retry.
- **Status:** G3 remains **Active**, SDK bridge remains authoritative. This is B0 only.
- **Owner:** `CancelQueuedDispatch` Effect service in `effect/app-runtime.ts` wired once into `AppLayer`. `SessionOperation` + `SessionRevision` + `ConfigConvergence` + `InstanceStore`/`ControlLease` are the sole authorities. No extension-local durable store, no second AppLayer/ManagedRuntime, no Promise facade.
- **HTTP adapter:** `DELETE /session/:sessionID/queue/:messageID` (`server/routes/instance/httpapi/groups/session.ts` `Schema.Boolean` with `400/404/409/500` declared errors, `handlers/session.ts`) synthesizes `requestId`/`opId = cancelQueued:<session>:<message>`/`idempotencyKey = legacy:<session>:<message>` and delegates to the shared service, preserving legacy `boolean` success shape and SDK. Typed `v:1` envelope (`succeeded`/`failed`/`ambiguous`, scrubbed `normalize`/`cap`, `revision: {session,config}`) is backend-internal; no `Unknown` weakening. `boolean` is returned only on `succeeded` (`cancelled:true/false`); `stale`/`conflict`/`ambiguous`/fence map to `409`, `scope_mismatch`/`validation.failed` to `400`, `session.not_found` to `404`, `internal` to `500`.

## Identity and guards

- Canonical `cancelQueued:<sessionID>:<messageID>` opId via `SessionOperation.cancelQueuedId` with strict `parseOpId` (`cancelQueued` kind, 2 segments) validated in `validateRequest`; caller cannot choose unrelated opId. `opKind` is `cancelQueued` (migrated from `task`, `session_operation` CHECK now includes `cancelQueued`).
- Hash: `sha256(idempotencyKey)` hex, `UNIQUE(session_id, idempotency_hash) WHERE NOT NULL` (`session/sql.ts`, migration `20260825000000_add_cancel_queued_metadata.ts`).
- Canonical directory from `SessionTable.directory` vs `context.directory`.
- `parentSessionId` must be `null` for this op.
- Stale vs replay ordering: exact idempotency lookup (`getByIdempotencyHash`) occurs before freshness guards, so same-key same-facts terminal replays even when its original revision is now stale. Stale checks apply only to new reservation: `context.sessionRevision < SessionTable.revision` → `stale` (revalidated transactionally inside `BEGIN IMMEDIATE` **after** idempotency lookup and **before** insert; only absent `(sessionID,hash)` undergoes stale validation; stale returns typed `failed` with no reservation or side effect); `context.configVersion < ConfigConvergence.getBootedVersion(canonicalDir)` → `stale` (re-read immediately before transaction and again before side effect; if config changed unfavorably after reservation, leave `in-flight` ambiguous and perform no side effect, do not delete reservation). Directory mismatch → `scope_mismatch`. All projected through `SessionOperation.normalize` scrub/cap with latest known `revision` (optional; never fabricated `0,0` or `+1/+2`; when authoritative reads fail, `revision` is absent and `internal` with best-effort fallback).

## Durable state machine

- Reserve `in-flight` (`cancelQueued` op) in one `BEGIN IMMEDIATE` before any queue side effect, with transactional idempotency lookup **before** session-revision stale guard (LOCK-301). Only absent key undergoes stale validation and insertion; same facts replay terminal without new revision or re-execution; differing facts → `conflict`; existing `in-flight` → `ambiguous` never re-executes.
- After reservation: `pending` true → `KiloSessionPromptQueue.cancelOne` → `Session.removeMessage` (EventV2 `MessageRemoved` projector advances one revision) → terminal `succeeded {cancelled:true}` (3 revisions total); `running`/not-pending → terminal `succeeded {cancelled:false}` (2 revisions). Terminal replay never calls `cancelOne`/`removeMessage` nor advances revision or changefeed; verified by durable `cancelQueued` row count and queue transition state (no fabricated revision count). This preserves the `MessageRemoved` projector as canonical delete path.
- `SessionRevision` reads `SessionTable.revision` (including `getTx` inside transaction); `ConfigConvergence.getBootedVersion` reads per-directory booted state (closure state, double-read pattern). No `Session.Info.version` misuse. No arithmetic revision guessing (`+1/+2`) or `{0,0}` fallback.

## Drain-control

- HTTP middleware snapshot-first lane remains valid. Shared dispatch invoked from an already-provided `InstanceRef` never reacquires. Non-HTTP callers without `InstanceRef` use `acquireDrainControl` (`InstanceStore.snapshot` + `ControlLease.acquire`, `409 InstanceUnavailableDuringConfigRebuild` when fence active without snapshot, otherwise normal `GenerationGate.acquire`+`InstanceStore.load` **plus** `ControlLease.acquire` held through full dispatch then released). Verified by direct `acquireDrainControl` no-snapshot active-fence `409` and normal-load lease-held tests. Running slot is never interrupted.

## Failure handling

- All observable failures are typed via `SessionOperation.normalize`/`scrub`/`cap` and returned as `failed`/`ambiguous` with `retryable` and best-effort `revision` (optional; absent when authoritative reads fail, never fabricated `0,0` or arithmetic `+1/+2`). **Only** `InstanceUnavailableDuringConfigRebuild` maps to fence `409`; snapshot/store/gate/DB/system errors map to typed `internal` with best-effort revision. Recovery/projection is defect-safe (inner `catch`/`catchDefect` never throws). Provider operation paths and existing tests are preserved. Legacy HTTP fallback maps dispatch defects directly to `InternalServerError` without fabricating a typed result.
