# P4.4-G3-B2 — Durable `session/update` title-only lane + private `session/update` fd3/fd4 parity (B2, G3 Active)

- **Scope:** B2 title-only durable lane for `PATCH /session/:sessionID` via `SessionUpdateDispatch` (`AppLayer`-owned). Legacy `metadata`/`permission`/`time.archived` PATCH remains compatible non-durable. No second transport, no generated SDK hand edits, no global process cleanup. Operation identity is canonical `sessionUpdate:<sessionID>:<operation-token>` (token stable across SDK/private for one semantic operation, distinct for successive renames; preserves externally visible prefix). Fixed `sessionUpdate:<sessionID>` no longer reused as primary key. Same `idempotencyKey` remains shared by SDK/private for one operation. One immediate transaction commits `title` + exactly one `session.revision` + one `changefeed` + terminal `session_operation` row with `result_snapshot` (serialized `SessionTable` row JSON converted/validated as `Session.Info`). Same-key replay returns persisted original terminal facts without mutation/revision/feed and without rebuilding from mutable current `Session` state. Private fd3/fd4 is parity-only: `dispatchPrivate` (replay/read-only) may return only already-committed durable terminal result; never becomes fallback executor after any SDK terminal, including `500`.
- **Status:** G3 remains **Active**, generated SDK `PATCH /session/{sessionID}` remains authoritative, private path is terminal-replay parity observation only. No transport cutover, no gate closure for C/D/E/F/P4.4, no cross-platform production claim beyond Darwin (Darwin production proof now exists via `server-manager-b2-integration.test.ts`; Linux/Windows not overstated). No extension-local durable store, no second `AppLayer`.
- **Locks:** B2-scoped `LOCK-B2-001` (SDK authoritative, private replay-only, no fallback after 500) → Phase LOCK-001, `LOCK-B2-002` (title-only lane, legacy compatible) → Phase LOCK-002, `LOCK-B2-003` (per-operation `sessionUpdate:<sessionID>:<token>` distinct, same `idempotencyKey` shared) → Phase LOCK-001/002, `LOCK-B2-004` (one commit, exact replay from persisted snapshot) → Phase LOCK-001, `LOCK-B2-005` (validate and bind all explicit identity fields, path/session/context mismatch typed) → Phase LOCK-001, `LOCK-B2-006`/`LOCK-B2-007` (reuse B1 fd3/fd4 ownership/lifecycle and capability `session/update`; parity observation-only) → Phase LOCK-001, `LOCK-B2-008` (B2 evidence/tracker/arch docs, no G3/Gates C-F/P4.4 claim) → Phase LOCK-003. ## Operation identity and storage

| Aspect | Behavior |
|---|---|
| OpId | `sessionUpdateId(sessionID, token?)` — `sessionUpdate:<sessionID>` base when no token (legacy compat), `sessionUpdate:<sessionID>:<token>` when token present. `token` is non-empty, no `:` . `parseOpId` allows 1 or 2 segments for `sessionUpdate`. |
| Token | `crypto.randomUUID()` per semantic rename, generated once in `buildSessionUpdateIdentity` and reused as both `opId` suffix and `idempotencyKey` suffix (`sessionUpdate:<sessionID>:<token>` identical). Distinct renames get distinct tokens → distinct `op_id` primary keys, no `SQLITE_CONSTRAINT_PRIMARYKEY` rollback. Same-key retry reuses identical `opId`+`idempotencyKey` → same `idempotency_hash` lookup. |
| Table | `session_operation` (`op_id TEXT PRIMARY KEY`, `op_kind CHECK IN ('prompt',...,'sessionUpdate')`, `title TEXT`, `result_snapshot TEXT` (JSON of serialized `SessionTable` row converted/validated as `Session.Info`), `revision INTEGER`, `idempotency_hash TEXT UNIQUE(session_id, hash) WHERE NOT NULL`, plus `directory`, `parent_session_id`, `config_version`, `session_revision`, `request_id`). Migration `20260830000000_add_session_update_snapshot` adds `result_snapshot`. |
| Commit | `insertSessionUpdateSucceededTx` in one `BEGIN IMMEDIATE`: `UPDATE session SET title=..., time_updated=now, revision=revision+1` → `SELECT` updated row → `JSON.stringify(row)` as `result_snapshot` → `INSERT session_operation` with `revision=nextRev` → `Changefeed.appendTx(session_id, revision, 'changed', now)`. Exactly one revision and one `changed` feed. |
| Replay | Fast-path `getSessionUpdateByIdempotencyHash` before tx and in-tx `getSessionUpdateByIdempotencyHashTx` check `isSessionUpdateConflict` (opId, directory, parentSessionId, configVersion, sessionRevision, title). If `succeeded`, decode and structurally validate serialized `SessionTable` row in `result_snapshot` against canonical `Session.Info` (validator beyond `object`/`fromRow` shape) and return validated snapshot with `makeRevision(existing.revision, currentConfigVer)` — not current `Session` row. Present-but-invalid object-shaped snapshot fails closed `internal` without fallback to mutable current `Session`; absent legacy snapshot is `internal` for private replay-only and public legacy fallback only where documented. `opId` PK collision checked before and inside `BEGIN IMMEDIATE` (`SessionOperation.get`/`getTx` by `op_id`) → typed `conflict` before any `title`/`revision`/`feed` mutation, no `SQLITE_CONSTRAINT_PRIMARYKEY` surfacing as `internal`. Fail-closed readers: `SessionRevision.get`/`ConfigConvergence.getBootedVersion` failures surface as `internal` without mutation, with config freshness linearized by a single continuous `GenerationGate` reader lease (statically verified, no release/reacquire gap; barrier active → `409 InstanceUnavailableDuringConfigRebuild` verified via active-barrier test) before mutation. |
| Private read-only | `dispatchPrivate` validates same as `dispatch` (`isAbsolute` directory, `SessionID` brand, `parentSessionId` must be `null` and **required** (omitted → `validation.failed`), `title` trim/200/control-char, strict `unexpected field` checks, `opId` session binding via `parseOpId` prefix), **same-key replay lookup/conflict precedes stale/config checks** and returns exact persisted terminal facts; checks `session.not_found` / `scope_mismatch` without mutating, then looks up by `idempotency_hash`: if not found → `failed internal no committed record` (no insert, no revision, no feed); if conflict → `failed conflict`; if succeeded → return persisted snapshot (invalid snapshot → `internal`). Never inserts. `fd-carrier.ts` routes `session/update` to `dispatchPrivate` **only**; missing `dispatchPrivate` fails closed `MethodNotFound` without mutation, **no fallback to `dispatch`**. |

## HTTP authority and identity binding

| Aspect | Behavior |
|---|---|
| HTTP `PATCH /session/:sessionID` | `requireSession` first. `isDurable` when any of `idempotencyKey`/`requestId`/`opId`/`context` present (no durable fields → legacy non-durable, preserved). Durable requires the complete tuple `title` + `idempotencyKey` + `requestId` + `opId` + explicit `context` (`directory` + `sessionId` required, `parentSessionId` optional in public contract but normalized to `null` after `context` presence, `configVersion`/`sessionRevision` optional freshness guards) — omitted `context` or partial tuple → `400`; `context.sessionId` must equal URL `sessionID` else `400`; `context.directory` is used verbatim with no fallback to current session directory, `parentSessionId` omitted in HTTP is normalized to `null` after `context` presence (private requires explicit `null`). No reachable fallback synthesis for `requestId`/`opId`/`idempotencyKey`/`directory`/`parentSessionId` without explicit `context` — missing tuple is rejected as `validation.failed`. `dispatch` maps `session.not_found→404`, `validation.failed/scope_mismatch→400`, `stale/conflict→409`, `internal→500`. Non-durable `title`/`metadata`/`permission`/`time.archived` path remains unchanged and creates no `session_operation`. |
| Private validation | `serve-private-peer.ts` `validateSessionUpdateRequest` mirrors backend: `isAbsolute` directory, `isSessionId` (`/^ses[^:]*$/`), `parentSessionId` **required and must be `null`** (omitted or non-null → `validation.failed`), `configVersion`/`sessionRevision` safe ints (`Number.isSafeInteger` ≥0), `payload.title` via `validateTitleStrict` (trim/200/control), strict root/context/payload `unexpected field` checks, `opId` parsed via `parseSessionUpdateOpId` and `parts[0]===sessionId` binding (allows token, rejects cross-session). `validateSessionUpdateResult` enforces `v/requestId/opId/op/idempotencyKey` identity, `status/accepted/outcome` coherence, `succeeded` data contains `title` or `session.title`, `failed` has matching `failure`/`outcome.failure`. |
| SDK type | `groups/session.ts` `UpdatePayload.context.parentSessionId` is `Schema.optional(Schema.NullOr(SessionID))` (allows `string | null`), `configVersion`/`sessionRevision` are `Schema.Int.check(isBetween(0, MAX_SAFE_INTEGER))` (finite safe integer, `type: integer minimum:0 maximum:9007199254740991` in OpenAPI). `UpdatePayload` root and `context` have `additionalProperties: false` (OpenAPI) and handler `updateRaw` rejects unknown fields via raw JSON `allowedRoot`/`allowedCtx` check before `Schema.decode`, consistent with dispatch `unexpected field` checks. Generated `packages/sdk/js/src/v2/gen/types.gen.ts` and `sdk.gen.ts` patched to `parentSessionId?: string | null` and `configVersion`/`sessionRevision?: number` (finite, no `NaN`/`Infinity`) and `packages/sdk/openapi.json` patched to `anyOf: [{type:string,pattern:"^ses"}, {type:null}]` (Hey API drops `null` otherwise; source `NullOr` correct). |
