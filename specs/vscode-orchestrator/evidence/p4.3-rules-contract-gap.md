# P4.3 Rules Contract Gap — Deferred Materialization (LOCK-006)

> **Scope: P4.3 evidence only. No runtime change.**

## Summary

- `rules` is a normative canonical typed-asset class registered in the extension registry/spec: `packages/kilo-vscode/src/config/types.ts:169` (`ASSET_DIRECTORIES` includes `"rules"`), validated in `packages/kilo-vscode/src/config/validate.ts` (`rulesFrontmatterSchema`), and normative in the runtime spec R10 — exactly as `agent`/`command`/`skill`/`tool`/`plugin` are.
- **Deferred gap:** The current opencode effective snapshot / materialization path (`packages/opencode/src/config/config.ts` + `packages/opencode/src/kilocode/config/config.ts` + `packages/opencode/src/kilocode/config/overlay.ts`) does **not** currently load `rules` assets into its effective snapshot. No opencode `ConfigAgent.load`-style `rules` loader exists, no `rules` collection appears in the overlay `Result`, and no composition operator is exercised for `rules` in this path.
- This is a contract gap, not a defect to be closed by inventing a P4.3 reader. Per LOCK-006, **no new rules runtime, loader, composition operator, or materialization subsystem is created in P4.3**. The asset class itself is preserved in the registry/spec and remains the normative canonical definition.

## What is true today

| Layer | `rules` status |
|---|---|
| Extension registry/spec R10 | Canonical typed-asset class; `rules/` directory under the global root and `canonicalRoot/.kilo/rules/` for project scope; not a top-level JSONC field. |

| Opencode effective config (P4.3 retained path) | Not yet consumed: no `rules` markdown scan/load in `config/config.ts` `loadInstanceState`, no `overlay.ts` `withAgents`-style `rules` path, no effective `rules` field in `Config.Info` / overlay `fields`/`collections`. |
| Guidance/architecture docs | Must describe `rules` as “canonical registered asset class” versus “currently materialized by this opencode path” — never as already effective in opencode. |

## Disposition

- Preserve the asset class in the extension registry/spec; do not delete `rules` from `ASSET_DIRECTORIES`, `validate.ts`, or R10.
- Do not add a rules loader, composition operator, or runtime subsystem in P4.3.
- Follow-up to define the opencode consumption/composition (loader, operator, snapshot participation) is explicitly deferred beyond P4.3. P4.3 exit may not claim rules are effective in opencode.
