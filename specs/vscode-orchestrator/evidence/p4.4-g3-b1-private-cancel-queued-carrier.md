# P4.4-G3-B1 — Private `session/cancelQueued` carrier over `kilo serve` fd3/fd4 (B1, G3 Active)

- **Scope:** Private carrier only for `session/cancelQueued` over existing `kilo serve` process extra fds into the same `AppRuntime`/`AppLayer` `CancelQueuedDispatch`. No new TCP listener, no Unix socket, no second runtime, no SDK generation, no second private path.
- **Status:** G3 remains **Active**, generated SDK HTTP/SSE remains authoritative, private path is terminal-replay parity observation only. No transport cutover, no gate closure for B/C/D/E/F.
- **Owner:** `CancelQueuedDispatch` Effect service wired once in `AppLayer` (`effect/app-runtime.ts`) is the single authority. `kilo serve` fd3/fd4 carrier (`kilocode/server/fd-carrier.ts`) and extension `ServerManager`/`KiloConnectionService`/`ServePrivatePeer`/`KiloProvider` are the only carrier consumers. No extension-local durable store, no second `AppLayer`/`ManagedRuntime`, no `Promise` facade.
- **Scope lock:** B1 is single-operation `session/cancelQueued` only; SDK remains authoritative with parity-only observation and no cutover; remaining families (fork/update/command/prompt/provider/config/private-query) deferred without new scope; Windows extra-fd remains residual pending actual Windows evidence (Darwin production evidence exists, Linux/Windows not overstated); evidence distinguishes Darwin real production composition proof from B0 deterministic deep state-machine proof.

## Carrier and protocol

| Aspect | Behavior |
|---|---|
| Spawn | `ServerManager` spawns `bin/kilo serve --port 0` with `stdio: ["ignore","pipe","pipe","pipe","pipe"]` (5 entries). `stdio[3]` is private writer, `stdio[4]` is private reader. `epoch` increments per spawn, `pid` is `serverProcess.pid`, both exposed on `ServerInstance`. Port discovery still reads `stdout` for `kilo server listening on http://127.0.0.1:<port>` — stdout remains unpolluted and `ServerManager` unit covers 5-stdio while preserving discovery. |
| Availability gate | `canUseFdCarrier()` requires `KILO_PARENT_PID` or `KILO_CLIENT=vscode` **and** both fd3 and fd4 `fstatSync` success. Both checks use `fs.fstatSync(3)` + `fs.fstatSync(4)`. Missing fds or missing env is fail-closed (`null` carrier, SDK remains authoritative). Bun keeps fd3 open as FIFO without peer — guard requires both fds, not just fd3. |
| Serve wiring | `ServeCommand` (`cli/cmd/serve.ts`) after `Server.listen(opts)` dynamically imports `kilocode/server/fd-carrier` and calls `tryStartFdCarrier()` (injectable `tryStartFdCarrierWithDeps` for tests). On failure it warns and keeps `null`. `shutdown` disposes the carrier before `InstanceRuntime.disposeAllInstances()` and `server.stop(true)`. |
| Protocol | JSON-RPC 2.0 over length-framed `JsonRpcPeer` (`private-worker/peer.ts` + `private-worker/frame.ts`). `initialize` carries `protocol: {name:"kilo-private", major:1, minor:0}`, `clientInfo: {name:"kilo-vscode"}`, `capabilities: ["session/cancelQueued"]`. Server validates via `validateProtocolVersion` (name must be `kilo-private`, major must be `1` — `ErrorCode.InvalidParams`), returns `buildInitializeResult()` with `protocolVersion "1.0"` and `capabilities ["session/cancelQueued"]`. Minor is ignored (1.5 accepted), major 2 is fail-closed. Second `initialize` after success is `InvalidRequest Already initialized`. Pre-init domain calls are `InvalidRequest Not initialized`. Unknown method is `MethodNotFound`. Malformed `Content-Length` sends `ParseError` and closes both peers idempotently; poison not processed. EOF pending rejection is `InternalError`. Supports pipelined frames and UTF-8 split, verified by carrier tests. |
| Dispatch | After `isInitialized()`, `fd-carrier.ts` routes `session/cancelQueued` via `AppRuntime.runPromise(Effect.gen { yield* CancelQueuedDispatchService; yield* svc.dispatch(params) })` — same `AppLayer` instance as HTTP `DELETE /session/:sessionID/queue/:messageID`. Typed `v:1` envelope (`succeeded`/`failed`/`ambiguous`, scrubbed `normalize`/`cap`, `revision?: {session,config}` optional) is shared. No new SDK code, no `Unknown` weakening. |
| Streams | `createFdCarrier(reader, writer)` resumes reader, creates `Peer` with `onClosed` that best-effort closes both streams. `dispose()` disposes peer and destroys both streams idempotently (double-dispose safe). Partial fd setup (`createReadStream` ok, `createWriteStream` throws) releases the first stream. `ServerManager.releasePrivateStreams` destroys `privateReader`/`privateWriter` on `exit` and `dispose()` without interfering with borrow, and kill is exact-PID only. |

## Extension lifecycle and ownership

| Aspect | Behavior |
|---|---|
| `ServerManager` | Owns child process lifecycle and the two private streams (`privateReader: stdio[4]`, `privateWriter: stdio[3]`). `epochCounter` increments per spawn; `releasePrivateStreams` destroys streams on `exit` (dying instance) or stale-spawn branch and on `dispose()` via `killProcess` exact PID/`process.pid` group. Never borrows or shares streams across managers. |
| `KiloConnectionService` | Owns `ServePrivatePeer` lifecycle. `privatePeer`, `privateAvailable`, `privateEpoch`, `privatePid` are cleared on `dispose()`, `resetConnection()`, and `handleServerExit()`. `initPrivatePeer(server)` is void-fired after `connectedPromise` in `connect()`, catches and warns, is epoch-coherent (stale epoch disposes), handles `!reader/!writer` unavailable fail-closed, handles `initialize` timeout/protocol-mismatch/capability-missing as unavailable, and logs negotiated pid/epoch. `isPrivateAvailable()` requires `privatePeer.isAvailable()` and `getState()==="open"`. `privateCancelQueued(req)` checks availability, then epoch/pid coherence: if `privateEpoch` drifted or `privatePeer` identity changed between call and return, returns `ambiguous transportUnknown true` with fresh `time`. `disposePrivatePeer()` is idempotent. |
| `ServePrivatePeer` | Wraps `JsonRpcPeer`. `initialize(timeoutMs=5000)` creates a fresh `JsonRpcPeer` with `onClosed` that marks unavailable only when epoch still current. Races `request("initialize",…)` against a `setTimeout` (unref). On success validates `protocol.name==="kilo-private"` and `major===1` (supports `protocolVersion string` or `{major}` object fallback), then checks capability includes `session/cancelQueued` (array or object form, empty object fails). Stores `capabilities` and `initRaw`, sets `available=true` only when epoch still current, otherwise disposes. Any throw/timeout/EOF/closed-state returns `false` with `available=false` and best-effort dispose, never throws. `privateCancelQueued(req)` validates via `validateCancelQueuedRequest` (`v===1`, non-empty `requestId`/`opId`/`idempotencyKey`, `op==="session/cancelQueued"`, `context.directory`/`sessionId` non-empty, `parentSessionId string|null`, `configVersion`/`sessionRevision` safe ints, `payload.messageId` non-empty, `opId===canonicalCancelQueuedOpId(sessionId,messageId)`). Then `peer.request("session/cancelQueued", req)`; on return validates coherence (`epoch`, `disposed`, `peer identity`, `state==="closed"` => `ambiguous transportUnknown`). Validates envelope via `validateCancelQueuedResult` (`v`, ids match req, `op`, `status` in `succeeded/failed/ambiguous`, `accepted` boolean, `outcome.type===status`, `time` finite, optional `revision {session,config}` safe ints, `succeeded` requires `data.cancelled boolean` and no `failure`, `failed` requires `failure`+`outcome.failure` code/message/retryable/detail must match, `ambiguous` requires `accepted===false` and no `data`/`failure`). Bad envelope returns `failed internal invalid private response shape`. Transport-closed/epoch-drift/disposed/`Peer closed`/`stale` returns `ambiguous transportUnknown true`; other errors return `failed internal` with `code`/`message`. |
| `KiloProvider.handleCancelQueued` | `SDK first, private second, SDK authoritative`. Calls `client.session.cancelQueued({sessionID, messageID, directory})` using `legacy:session:message` durable key and `cancelQueued:session:message` opId. On `sdkRes.error` shows `showErrorMessage` but still evaluates parity gate. `isPrivateAvailable` defaults false. Terminal gate uses authoritative `response.status` first (`response.status` integer 100-599, string numeric accepted): `400/404/409/500` is terminal, otherwise non-terminal even if `error` present; with no `response.status` it falls back to `error.status/statusCode/code/httpStatus` numeric/string `400/404/409/500`, message regex `\b(400|404|409|500)\b`, and `_tag` including `badrequest/notfound/conflict/internal`. Non-terminal `429` etc does **not** trigger private. When unavailable or non-terminal, returns without private call. When terminal and available, builds `privateReq {v:1, requestId:crypto.randomUUID(), opId, op, idempotencyKey:"legacy:…", context:{directory, sessionId, parentSessionId:null}, payload:{messageId}}` and calls `connectionService.privateCancelQueued` with 3000 ms timeout: timeout/throw maps to `ambiguous transportUnknown true`. Then `compareParity(priv, sdkRes)` observation only — divergence and match are `console.warn`/`console.log` (`[Kilo PrivateParity] divergence` with `opId/sessionID/messageID/divergence/details/privStatus/transportUnknown`, `[Kilo PrivateParity] parity match`), never influences user-visible cancel result or second operation. SDK boolean remains the only user-facing outcome. |
| Restart / reinitialize | `ServerManager` `epochCounter` proves replacement server has new `epoch`/`pid`/`port` with 5 stdio. `KiloConnectionService` disposal kills exact `pid` (SIGTERM then SIGKILL fallback) and verifies `process.kill(pid,0)` throws before resolving; decoy pid outside ownership is never killed (exact-PID test). `ServePrivatePeer` init after restart re-negotiates and reaches `available`. Null streams remain fail-closed while SDK HTTP still succeeds. |

## Parity — observation only, never authoritative

`serve-private-peer.ts` `compareParity(priv, sdk)` (`sdk: {data?, error?, response?}`) is pure observation, not a transport cutover:

- `transportUnknown true` (any `priv` status) → divergence `transport-unknown`, terminal-equivalent is not claimed.
- `priv ambiguous` (no `transportUnknown`) + `sdk failed 409` → no divergence (real transport-closed converges to 409 fence class); otherwise status-mismatch when sdk succeeded.
- `sdk succeeded` vs `priv succeeded` → requires `sdk.data` (`boolean` cancelled) === `priv.data.cancelled`, otherwise `cancelled-mismatch`.
- `sdk failed` vs `priv failed` → class mapping via `response.status` actual SDK tuple (preferred before `error` heuristics): `400` allows `validation.failed/scope_mismatch`, `404` allows `session.not_found`, `409` allows `stale/conflict/InstanceUnavailableDuringConfigRebuild`, `500` allows `internal`; mismatch is `failure-class-mismatch`. Fallback without `response.status` allows exact `code` equality when SDK provides a non-numeric code.
- All other cases with same status and no transport-unknown are no divergence.

SDK generation and HTTP/SSE remain the only authoritative path. Private result at most logs; `handleCancelQueued` never replays, retries, or replaces the SDK boolean, and duplicate `idempotencyKey` reuses the durable terminal without a second queue transition (verified by both B0 dispatch tests and B1 production replay).
