## Systemic lifecycle / fork ownership hardening

| Area | Hardened behavior |
|---|---|
| `JsonRpcPeer` ownership | `requestWithId` allocates exact `id` atomically (`nextId++`) and registers `pending.set(id, {resolve,reject})` before `write`; `getPendingIds()`/`peekNextJsonRpcId()` inspectable. `tryCancelPending(id, message)` removes exactly one entry, rejects with `InternalError` `message`, returns `true` if present else `false`. Writer synchronous throw (`write` throws) → `transitionClosed("writer sync throw")` → `rejectAllPending("Peer disposed")` → `state="closed"` and subsequent `request` rejects immediately without leak. Writer async error (`emit "error"`) → same closed transition. EOF/stream `close`/`error` also transitions to `closed`. Malformed `Content-Length` frame → `ParseError` + `transitionClosed("malformed framing")`. All paths ensure `pending.size===0` after close and pending settle within next tick. Verified by `peer-writer-timeout.test.ts` 4 pass 21 expects and `session-create-private.test.ts` exact-id allocation. |
| `ServePrivatePeer` lifecycle | `initialize()` is serialized — concurrent second `initialize()` shares the same in-flight promise and does not issue second wire `initialize`; stale completions after `dispose()` are rejected and do not mark `isAvailable()` true. Late `initialize` after `dispose()` stays `isAvailable()===false` even if backend later responds. Failed `initialize` (timeout after 100 ms in test, 5000 ms production) invalidates transport — same instance second `initialize()` stays `false`, new instance reusing same streams stays `false`; only fresh `PassThrough` succeeds. Stale same-epoch `onClosed` guard cannot disable current peer — current `isAvailable()` stays `true` after disposing an old peer that captured same epoch identity. Verified by `lifecycle-hardening.test.ts` 10 pass 56 expects (includes concurrent, late-after-dispose, stale-close, failed-invalidate). |
| `ServerManager` process ownership | Startup `getServer()` spawns `bin/kilo serve --port 0` with 5 stdio, port discovery via `stdout` `kilo server listening on http://127.0.0.1:<port>` with `stdio.length===5`, `privateReader`/`privateWriter`/`pid`/`epoch` stored; dead process after port detection (script prints port then exits in next tick) is not cached (`instance===null` after 200 ms). Dispose during startup kills only exact `startingProc.pid` via SIGTERM then SIGKILL fallback (30 s prod → 600 ms test via patched `setTimeout`), then clears `startupPromise===null` and verifies `process.kill(pid,0)` fails for owned while decoy pid stays alive; watchdog timers cleared. Startup timeout (30 s prod → 600 ms test) with non-exiting child kills exact owned child with SIGTERM then SIGKILL fallback, owned dies, decoy stays alive. All paths verify decoy untouched (exact PID kill). Verified by `lifecycle-hardening.test.ts` 3 server-manager hardening tests. |
| `KiloConnectionService` connection ownership | `connect()` acquires `ServerManager.getServer()` plus `privatePeer.initialize`; `resetConnection()`/`handleServerExit()`/`dispose()` all call `disposePrivatePeer()` idempotently and clear `privatePeer`/`privateAvailable`/`privateEpoch`/`privatePid` and `client`/`sseClient`/`info`. Dispose during `connect()`'s `getServer()` delay invalidates pending connect continuation — `connect` promise rejects with `Error`, `client`/`sseClient`/`privatePeer` stay `null` after, and a late `connect(storage)` after dispose rejects without resurrecting stale `client`. Verified by `lifecycle-hardening.test.ts` `KiloConnectionService dispose invalidates pending connect`. |
| Fork filesystem ownership (LOCK-002 systemic) | Target `SessionID` strict occupation check before any FS write (`SessionTable.id` + `EventSequenceTable`/`EventTable` aggregate + `SandboxStore.read` + `storageFile(baseKey + session_diff)` absent; strict IDs). Established `ownedBase`/`ownedDiff`/`ownedSandbox` flags only after successful exclusive `wx` claim; `EEXIST` on claim → `conflict` typed, no blanket `remove`. Probe errors other than `ENOENT` → `internal` fail-closed (never treated as absent). Partial exclusive failure (first `wx` succeeds, second fails) cleans only owned via direct `fs.rm` of owned path (`storageFile(baseKey)`) — not pre-existing file, with flags cleared only after **all required cleanup for that owned artifact succeeds** (`okStorage && okFs` or `okRemove && okEvict`), retained on cleanup failure with `Effect.logWarning` `{target, cause}` without masking original fork failure. Normal failures (`failFirstDiffWrite`/`failSecondDiffWrite`/`failSandboxWrite`/`failTxAfterFs` seams) compensate only attempt-owned artifacts; pre-existing target `EventSequence`/`EventTable` aggregate without `SessionTable` maps to same typed `fork target already exists` `conflict` with no FS/DB mutation and original event preserved (verified by `session-fork-event-preflight.test.ts` 2 pass 40 expects with full no-mutation assertions for both orphaned aggregate and sequence-only cases); deterministic `failCleanupFs`/`failCleanupStorage` injection proves original fork error preserved, cleanup warning `{target, cause}`, flag retained as file remains (verified by `session-fork-ownership.test.ts` 10 pass 87 expects); pre-existing session family artifacts outside attempt remain; legacy `Session.fork` additionally removes the `EventSequence`/`EventTable` `session.created` aggregate scoped to the forked `SessionID` on late failure (preserving unrelated aggregates). Post-crash interruption between FS `wx` and `DB BEGIN IMMEDIATE` commit may leave orphaned FS artifacts; no automatic recovery subsystem claims cross-resource crash atomicity — orphan residual is explicit/unclaimed and preserved under existing family cascade semantics only (not claimed as claimed). Post-commit `SandboxPolicy.inherit` is best-effort `catch(() => void)` so the DB-committed session row + `result_snapshot` + `EventV2` remain valid even if inherit fails. Verified by `session-fork-ownership.test.ts` 10 pass 87 expects + `session-fork-persistence.test.ts` 8 pass 56 expects + `session-fork-event-preflight.test.ts` 2 pass 40 expects. |
